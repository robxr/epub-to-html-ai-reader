# EPUB 转 HTML · AI 批注阅读器

每本书输出一个可独立打开的 HTML。需要跨书复习时另附离线笔记书架。以下命令以技能目录为起点。

## 选择交付方式

- 只要转格式时，直接转换。保留书中可识别的精读划线和索引；让用户自行添加笔记。
- 按问题精读时，从请求中提取想解决的问题、每次可用时长和深度。快速了解侧重结论与边界，系统学习侧重概念之间的依赖，找素材侧重可准确引用的证据。信息够用就开始；只有目标缺失且不同选择会明显改变选段时，才问一个简短问题。用户只说“精读”时可按书的主题拟一个目标，注明这是默认选择。
- 先读用户提供的精读偏好文件或文字。长期偏好可迁移到新书；书名、具体问题和本次阅读顺序按当前任务决定。
- 输入可以是一本、多本或一个目录。对同书多个版本按用户指定选择。未指定时输出到独立目录，避免覆盖已交付的阅读器。

## 从试读到整书

1. 运行 `python3 scripts/epub_reader.py extract "书.epub"` 列出章节；以 `--chapter "章节 ID"` 提取包含段落 ID 的原文。先浏览目录和候选章节，记录哪些章节能回答目标。
2. 阅读[批注格式与选段规则](references/annotations.md)。选一段真正代表本书难度和论证方式的材料，写少量可定位的试读批注，包含一条有价值的条件或例外（原文有依据时）。用 `study.stage = "preview"` 生成试读 HTML，放在单独目录。展示选段理由、作者观点、AI 解读及一道能从引文回答的问题。
3. 用户想先校准时，交付试读并等待反馈。可直接回复“我已懂定义，多选反例”，或从路线页导出偏好交给助手。把反馈变成具体的选段、密度或深度规则，并在下一批应用。若已明确要求一次完成、授权按默认偏好继续或提供了成熟偏好，直接交付完整版，不额外设确认环节。
4. 对照实际读过的章节写正式批注。给有贡献的段落稳定编号，保留仍适用的试读编号；保留用户的原始笔记。按问题和先修概念编排每次阅读，提供选读理由和包含思考时间的时长估计。路线只引用已校验的批注。将确实无法回答的部分记入 gaps，区分“已读范围未见依据”和“尚未审阅”。不要求每章有批注。
5. 用 `study.stage = "full"` 转换。检查每本书的结果和退出状态。修正无法定位的引文或无效路线，核对从路线和卡片能回到原句。不要把未完成审阅的章节标成已精读。交付时说明处理范围、每本批注数量、路线、未覆盖的问题和可打开的文件。

## 转换、书架与备份

```bash
python3 scripts/epub_reader.py convert "书.epub" --annotations "试读.json" --out-dir "试读"
python3 scripts/epub_reader.py convert "EPUB目录" --annotations "批注目录" --out-dir "精读版" --shelf
python3 scripts/bookshelf.py "精读版" --output "精读版/笔记书架.html"
```

按目录转换时，批注文件名为 `原书名.annotations.json`。省略 `--annotations` 时会在 EPUB 旁查找同名文件。只重建用户指定的输出；已有单书阅读器需要 `--overwrite`。单独生成书架时可用 `--backups` 传入各书从阅读器导出的批注 JSON，把个人改动纳入检索。将书架与书的 HTML 按原来的相对位置一起交付。

从「卡片」进入主动回忆，先自行回答，再展开答案、引文并记录掌握情况。JSON 备份用于跨设备迁移个人改动、删除记录和复习进度；Markdown 用于整理引用。重建旧阅读器时保留书与批注的稳定标识，提醒用户先导出备份，再在新版阅读器中导入核对。书籍正文与个人批注默认只交付给当前用户。
